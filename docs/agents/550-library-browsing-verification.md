## Baseline findings

- **550-B / P2 / status and recovery:** Albums, Artists, Genres and Playlists use empty-array placeholders before their first shared read. They draw empty copy while loading. Shared-query first failures leave the same empty UI indefinitely; Songs and Favorites instead stay blank. A scan error banner cannot explain a database read failure. Expose first-read loading/failure and explicit targeted Try Again, keeping the last good result during refresh and the existing shared-read lifecycle. Test the Core registry public API, already authorized by the implementation brief.
- **550-C / P2 / adaptivity:** `PlaylistsHeader` puts its count and two text actions in one non-wrapping row; `PlaylistsButtons` also disallows wrapping. The count has no width once the actions consume the available width. Permit the count/actions to wrap on a narrow or enlarged-text layout. Rendered before/after evidence is PENDING.
- **550-D / P1 / accessibility:** Albums maps two letter starts to the same grid row. `spineStep` derives each step solely from the top row, resolving ties to the last letter there. Repeated decrement can return the same earlier letter forever. Preserve the last explicitly chosen letter while its row is still current so every letter is reachable. Test forward/backward traversal, row changes and reverse sorts through the Core public spine API.

Fixed-height 56dp rows/tile captions remain a render-verification risk inherited from the parent register, not a new confirmed clipping claim. No speculative font-metric/indexing change is planned.

## Corrections and source confirmation

- **550-B:** the existing Core shared-query registry now exposes first-read `loading/error/ready` and an explicit `retry(key)`. Its optional state callback is separate from result delivery: no additional read or route observer. `useLibraryQuery` observes a stable result-or-state snapshot; the result box remains unchanged during refresh. Albums/Artists/Genres/Playlists wait for a real answer before empty copy; Songs/Favorites show named, still skeletons. First failure offers a scrollable, inset-aware Try Again with polite error copy and the existing 48dp text button. A failed new Songs sort retains the old list plus targeted recovery. Find in Songs keeps its field/query/keyboard while metadata reads or retries; it never calls an unread query a no-match. Scope is local data only; no network policy or scan behavior changes.
- **550-C:** header count and action group can wrap; the action group also wraps its two controls when needed. Normal layouts retain the count/action hierarchy and existing action labels. No width breakpoint, font cap or playlist behavior change.
- **550-D:** `spineStep(entries, row, direction, chosenLetter?)` uses the explicit letter only while its section row remains current. The native index passes its last choice. Same-row letters are individually traversable in both directions; a manually scrolled section supersedes an old choice. Reverse orders and `#` retain list order. Touch scrubbing, haptics, plate animation, spine dimensions and instant list jumps are unchanged.
- **550-E:** the absolute tile drag handle is at least 48×48dp and stays centred on the existing name line. List-mode targets remain 48×56dp. Playlist cell geometry, virtualized windowing, drag/drop rules, custom-order switching and semantic Move up/down actions are unchanged. This is a layout-prop correction; no constant-mirroring test was added.
- **550-A (historical):** handled finder result taps/on-drag keyboard dismissal remain present in Songs, Artists and Favorites. Do not count them as a new implementation.

Core public behavior tests ran red before the registry/spine implementations, then green. They verify first failure vs empty, no automatic retry loop, one shared Retry attempt, no unrelated query read, retention of good content on refresh failure, disposed-read isolation, all same-row letters/edges, manual scrolling and reverse order. Native props and integrations require the device matrix below; source confirmation does not establish actual TalkBack or rendered acceptance.
