## Implementation and platform delivery inspection

Previously `lyricStoryBackground` returned the selected colour for both endpoints. `LyricCardPreview` fitted the card directly into its available area. `ShareModule.shareToInstagramStory` sent the card as a sticker with no size or position information. This source inspection explains the identical background colour and the lack of exported smaller framing; it is not a reproduction on the owner's APK.

The new public Core decisions are:

- `lyricStoryBackground`: derive two complementary tones from the selected solid. Move both toward the same contrasting neutral, keeping the fade from crossing the card colour. Tested examples cover red, light artwork colours, dark artwork colours, black, white, grey and missing artwork. Invalid colours fall back to graphite before deriving the gradient. The card's colour selection, ink and typography decisions are unchanged.
- `lyricStoryFrame`: centre the adaptive card inside 80% of a 1080 × 1920 canvas's width and 75% of its height, preserving its proportions. A short square card occupies `(108, 528, 864, 864)`; a full-height 9:16 card occupies `(135, 240, 810, 1440)`. Corner radius is 5.5% of the visible card width. The decision depends on lyrics, not palette selection.

`LyricCardPreview` uses those same colours and frame values to show a Story behind the solid card. Its captured `LyricCard` remains the existing standalone square-cornered card. The native `StorySticker.write` renders that card through an anti-aliased rounded rectangle onto a separate transparent ARGB PNG, at the shared frame's bounds. It writes a new cache file and leaves the original intact. Rendering happens in the native asynchronous export function before launching Instagram, not as a preview-only scale transform.

The delivery path is `useImageShare` → `shareImageToInstagramStory` → `deliverInstagramStory` → native `writeStorySticker` → native `shareToInstagramStory`. The final intent remains:

- action `com.instagram.share.ADD_TO_STORY`, package `com.instagram.android`, MIME `image/png`;
- the **new padded PNG** as `interactive_asset_uri`, with Instagram alone explicitly granted read access;
- the selected solid colour's distinct gradient endpoints as `top_background_color` and `bottom_background_color`;
- the existing Facebook App ID as `source_application`;
- no flattened Story background image and no added placement/scale extras.

The separate PNG keeps the lyrics on Instagram's editable sticker layer. Transparent padding carries the intended smaller visible card inside that asset. It does **not** establish that Instagram honors a particular initial screen coordinate or scale: Instagram owns the outer sticker placement and could trim transparent padding. This implementation does not claim otherwise. Exact outer placement, initial size, transparency retention and drag/pinch behavior remain to be measured in the actual editor.

For contract context, the existing integration follows Meta's [Sharing to Stories](https://developers.facebook.com/docs/instagram-platform/sharing-to-stories/) intent. A fresh documentation fetch in this session returned HTTP 429; the legacy documentation URL was also inaccessible. No current undocumented geometry extras or host behavior were inferred from a successful live documentation fetch.

Standalone Save image, WhatsApp and More still use the unpadded card PNG at its adaptive dimensions. Song and Recap do not opt into `storyFrame`; Recap's solid Story background is now independent of the changed lyrics helper. Destination availability, App ID checks and the existing error toast remain in place. A sticker-render failure rejects instead of silently sending an unframed card.
